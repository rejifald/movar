# Movar Audit kernel — `@movar/audit`

> The adjudication half of Movar Audit: `evaluate(evidence, ruleset) → Report`, pure, zero I/O, zero DOM. Collectors live in each runtime and share nothing but the serializable `Evidence` they emit — which is what makes the same judgement run in CI and on a phone, and makes a published finding replayable and falsifiable by the site it names.

## What it does

- **`evaluate(evidence, ruleset) → Report`** (`src/evaluate.ts`) — the kernel. Derives the capability set from the evidence's shape, gates every rule on it, iterates pages for page-scoped rules, grades every finding, and stamps the ruleset and the evidence onto the report.
- **The evidence model** (`src/evidence.ts`) — a serializable _structural digest_: declared `lang`, hreflang alternates, the picker model, link targets, body text-node samples with node paths and **how many nodes they are a sample of**, the head's declared and text surface, and per-probe status / headers / redirect chain. Never raw HTML. `source` is a discriminated union (`network` | `filesystem`) and probes live on the network branch only. Growth is additive and versioned: `head` arrived in `schemaVersion` 2, `textSampling` in 3 and `ProbeEvidence.redirectChainTruncated` in 4, all optional, so a stored older bundle still replays — the rules that read the head report `not-applicable` naming the schema, the denominator falls back to the sample count it can see, and an absent truncation flag reads as "this chain reached its own end", which is what every chain a pre-v4 collector kept was. Version 5 is the one bump that added no field: a `TextNodeSample.nodePath` now points at the passage rather than at the element around it (see the gotcha below), and since nothing recomputes a stored bundle's paths, the version is what says which of the two contracts the paths in a bundle were written under.
- **Capability derivation** (`src/capability.ts`) — `static` / `http` / `matrix` / `traversal` / `multi-vantage` / `browser` / `site`, computed from the evidence alone. Absent capability → `not-collected`, automatically.
- **The grading law** (`src/grading.ts`) — grounding decides failing power. `declared` and `observed` may `fail`; `classified` never can, and the kernel downgrades it. `classified` findings must carry a `denominator`; jurisdiction-pack findings must carry a `citation`.
- **The rule contract** (`src/rule.ts`) — `Rule`, `RuleContext<S>`, `RuleOutcome`, and the `pass()` / `notApplicable()` / `findings()` outcome helpers. A family is one file exporting one `RuleFamily`.
- **Suppressions** (`src/suppress.ts`) — the only sanctioned way to opt out of a rule, since the ruleset floats and cannot be pinned. Follows the house doctrine of [`check-suppressions.mts`](../../scripts/check-suppressions.mts): an allowlist (derived from the grading law — never a pack rule, never a `classified` rule), no blanket ignores, a mandatory justification, a budget that only ratchets down, and stale-entry detection. **A suppression never rewrites the `Report`** — `evaluate()` is the instrument, and what blocks a build is the caller's policy.
- **The classifier seam** (`src/classifier.ts`) — `Classifier` over `@movar/lang-detect`'s snippet ladder, franc-free by default. It runs _inside_ `evaluate()`, so stored evidence re-adjudicates against an improved classifier.
- **The shared models rule families read** — `src/inventory.ts` (the declared [language inventory](../../docs/glossary.md#language-inventory), kept un-flattened so disagreement _between_ sources is expressible), `src/locator.ts` (resolving a declared target against the collected page set, normalized — never by fetching), `src/text-samples.ts` (what text may be classified at all, and the denominator). Each exists because three or more families need the same answer and must not drift into different ones.
- **All 46 rules**, in six families:
  | File | Family | Rules |
  | --- | --- | --- |
  | `src/rules/page-declaration.ts` | A — page declaration (WCAG 3.1.1 / 3.1.2, plus the head declaration surface) | 9 |
  | `src/rules/inventory.ts` (barrel over `inventory-sources.ts` + `inventory-hreflang.ts`) | B — inventory | 15 |
  | `src/rules/serving.ts` | C — serving (the response matrix) | 7 |
  | `src/rules/switch.ts` | D — switch integrity | 4 |
  | `src/rules/content-language.ts` | E — content language (classifier-only, never fails) | 5 |
  | `src/rules/ua.ts` | F — `ua` jurisdiction pack (Law 2704-VIII Art. 27 §6) | 6 |

## Boundaries & invariants

- **Pure kernel** — no `fetch`, no filesystem, no `jsdom`, no DOM globals, no clock, no randomness. The same bundle must always produce the same report; that is the whole falsifiability claim.
- **The collector splits by what is runtime-specific, not by convenience.** `src/collect/digest-dom.ts` (any `Document` → evidence) and `src/collect/assemble.ts` (the `Link` grammar, page identity) are shared by every runtime and must stay free of `jsdom` and `node:*` — the Safari host app imports them straight into a Vite bundle. `purity.test.ts` asserts that, because neither failure shows up in this package's own Node-run tests. `digest.ts` (jsdom parse + the globals shim) and `node.ts` (fs, robots, declared-target traversal) are the Node-only halves.
- **`Evidence` and rule IDs are the public API**, not this module graph. IDs are never renamed once published — a suppression pointing at a renamed rule silently stops suppressing.
- **`not-collected` is never `pass`.** Silently passing what it did not check is the default failure mode of every audit tool.
- **A page rule's `pass` carries the pages behind it.** The same refusal, one level down: the kernel puts `pagesAdjudicated` / `pagesNotApplicable` on every page-scoped `RuleResult` it invokes, and sums them into `coverage.rulePagesAdjudicated` / `rulePagesNotApplicable`, so a rule that judged one page of three cannot be read as having looked at the site. The verdict is unchanged — a rule that judged a page and found it fine did `pass` — but the report is no longer silent about the other two.
- **No rule hand-checks for missing data.** The kernel answers `not-collected` before `run` is called, so inside `run` the context is already known to satisfy the contract.
- **`classified` can never `fail`.** Enforced by the type on a pure-classified draft, and by the kernel's downgrade on a hybrid `via: 'classified'` finding. A mis-written rule cannot manufacture a build-breaking accusation.
- **Attachments are citable, never readable.** `Attachment` carries a hash, a size, and a media type, and deliberately no content field — so `evaluate()` replays identically whether or not payload capture was on.
- **No inference.** Language inventory comes only from what the site declares. Probing `/uk/` to guess at an undeclared translation is forbidden — a false accusation is the one failure mode that ends the product.
- **No per-site adapters.** A checker with an allowlist is not a standard, and it would contradict the standing claim that Movar works via common mechanisms.
- The extension shares the model packages and **never the judge** — wiring this engine into a content script would put audit rules on the page-load hot path.

## Public API / entry points

One entry point plus a `./*` wildcard subpath (`@movar/audit/rules/page-declaration`, …). The barrel is `src/index.ts`.

### The kernel

- `evaluate(evidence: Evidence, ruleset: Ruleset): Report`

### Evidence

- `Evidence` — `{ schemaVersion, source, collectedAt, collector, pages, attachments? }`
- `EVIDENCE_SCHEMA_VERSION` — the wire-format version a bundle is written with
- `EvidenceSource` = `NetworkSource | FilesystemSource`; `NetworkSource` = `{ kind: 'network'; vantage; probes; robots }`, `FilesystemSource` = `{ kind: 'filesystem'; root }`
- `Vantage` — `{ id; kind: 'local' | 'proxy' | 'relay'; country?: VantageCountry }`
- `VantageCountry` — `{ claimed: string; verified?: boolean }` — a **claim**, never a measurement
- `PageEvidence` / `DocumentEvidence` / `ProbeEvidence` / `PickerEvidence` / `TextNodeSample` / `TextSampling` / `LangAttribute` / `AlternateLink` / `LinkTarget` / `RedirectHop` / `Attachment` / `ScreenshotViewport` / `Rect` / `NodePath`

### Capabilities

- `Capability` — `'static' | 'http' | 'matrix' | 'traversal' | 'multi-vantage' | 'browser' | 'site'`
- `deriveCapabilities(evidence): ReadonlySet<Capability>`
- `adjudicableProbes(evidence): readonly ProbeEvidence[]` — drops `blocked` / `error` probes
- `missingCapabilities(required, available): readonly Capability[]`

### Findings and grading

- `Finding` — the graded shape in a report; `FindingDraft` = `ClassifiedFindingDraft | GroundedFindingDraft` — what a rule emits
- `Verdict` — `'pass' | 'fail' | 'warn' | 'not-applicable' | 'not-collected'` (rule level)
- `FindingVerdict` — `'fail' | 'warn' | 'observation' | 'info'` (finding level)
- `Grounding` — `'declared' | 'observed' | 'classified'`; `Via` — `'declared' | 'classified'`
- `Citation` / `Denominator` / `EvidenceRef` / `FindingSubject` / `FindingScreenshot` / `RuleScope`
- `effectiveGrounding(grounding, via): Grounding`
- `gradeFinding(rule, draft): Finding`; `RuleContractError`

### The rule contract

- `CoreRule<S>` — `{ id: \`core/${string}\`; title; capabilities; grounding; hybrid?; scope: S; run(ctx: RuleContext<S>): RuleOutcome }`
- `PackRule<S>` — the same plus a mandatory `citation`, for any ID outside `core/`
- `Rule` = `CoreRule<'page'> | CoreRule<'site'> | PackRule<'page'> | PackRule<'site'>`
- `RuleContext<S>` — `{ evidence; capabilities; pages; probes; page: S extends 'page' ? PageEvidence : null; classify }`
- `RuleOutcome` + `pass()` / `notApplicable(reason)` / `findings(...drafts)`
- `RuleFamily` — `{ id; title; rules }`; `ruleCitation(rule): Citation | null`

### The artifact

- `renderReportArtifact({ report, evidence, target, generatedAt }): string` (`src/artifact.ts`) — the ADR §8 deliverable: **one self-contained HTML file** carrying the readable report, the embedded `{evidence, report}` bundle, and the replay command. Pure, so `generatedAt` is a parameter rather than a clock read. Every interpolated value is escaped (it all originates from an audited third-party site), and the embedded JSON escapes `<` so a page containing `</script>` cannot break out of the bundle block. The CLI and the host app render the same document — they must not drift into two artifacts.

### Suppressions

- `applySuppressions(report, policy): SuppressionOutcome` — `{ suppressed, remaining, stale, violations }`; the report is returned untouched
- `parseSuppressionPolicy(value): SuppressionPolicy | Error` — validates parsed JSON without doing I/O
- `Suppression` / `SuppressionPolicy` / `SuppressedFinding` / `SuppressionViolation` / `SuppressionOutcome` / `MIN_REASON_LENGTH`

### Rulesets, classifier, report

- `createRuleset({ id, version, families, classifier? }): Ruleset`; `RULESET_VERSION`; `DuplicateRuleIdError`
- `CORE_RULESET` — families A–E, 40 neutral rules, **no jurisdiction pack**
- `UA_PACK_FAMILIES` + `withPack(base, ...families): Ruleset` — statute rules apply only where a caller composes them in
- `Classifier` / `ClassifiedText` / `createSnippetClassifier(rung3?)`
- `Report` / `RuleResult` / `RulesetStamp` / `EvidenceStamp` / `CoverageSummary` / `REPORT_SCHEMA_VERSION`
- `isWellFormedBCP47(tag)` / `primarySubtag(tag)` / `declaredLanguageOf(tag)` / `urlLanguageMarker(locator)` / `UrlLanguageMarker`
- `siteInventory(pages)` / `pageInventory(page)` / `alternateLanguage` / `pickerOptionLanguage` / `inventoryCandidates` / `LanguageInventory` / `InventorySource` / `INVENTORY_SOURCES` / `X_DEFAULT`
- `parseLocator(href, base?)` / `locatorOf(page)` / `resolveTargetPage(pages, from, href)` / `resolvesToCollectedPage` / `Locator`
- `classifySamples` / `dominantSampleLanguage` / `classifiableSnippet` / `classifiablePageLanguage` / `textNodeDenominator` / `CLASSIFIER_CANDIDATES` / `MIN_CLASSIFIABLE_CHARS` / `MAX_CITED_PASSAGES` / `ClassifiedSample` / `DominantLanguage`
- `pageDeclarationFamily` / `inventoryFamily` / `servingFamily` / `switchFamily` / `contentLanguageFamily` / `uaPackFamily`

### The dogfood gate

`nx run marketing:audit` (the `audit-site` CI job, and part of `pnpm validate`) runs this
package's CLI over `apps/marketing/dist` with
`apps/marketing/audit-suppressions.json` as its policy — we judge movar.fyi by the same 40
core rules we judge everyone else with. Two consequences worth knowing before you touch a
rule:

- **A new rule can turn this repo's own CI red**, by design. The ruleset floats; that is the
  bar rising. Fix the site, or add a justified suppression — never pin.
- **A rule that stops firing turns it red too**, via stale-suppression detection. That is the
  same mechanism working: the entry has outlived its finding and should be deleted.

The `ua` pack is deliberately not composed in there. movar.fyi declares no Ukrainian-market
signal, so Law 2704-VIII does not apply to it and must not even be evaluated.

### Adding a rule family

1. Write `src/rules/<family>.ts` exporting one `RuleFamily`. Annotate each rule as `CoreRule<'page'>` / `CoreRule<'site'>` (or `PackRule<…>` for a jurisdiction pack) so the contextual types apply.
2. Declare `capabilities` honestly. The kernel answers `not-collected` on your behalf — never write a guard for missing data.
3. Emit drafts with `findings(...)`; the kernel stamps `rule`, `scope`, and (for a pack rule) `citation`.
4. Register the family in `ruleset.ts` — one import, one array entry.
5. Co-locate `src/rules/<family>.test.ts` and drive it through `evaluate`, not through `run` directly, so capability gating and grading are covered too.

## Gotchas

- **`normalizeBCP47` is not a well-formedness oracle.** It returns `null` for any tag outside Movar's alias set (`de-DE` → `null`), which is right for "should Movar act on this?" and wrong for "is this malformed?". Use `isWellFormedBCP47` for the grammar and `declaredLanguageOf` for the comparison — but **never `declaredLanguageOf` raw on an `hreflang` value**: `declaredLanguageOf('x-default')` is `'x'`, because `normalizeBCP47` returns `null` and it falls through to `primarySubtag`. `x-default` is a routing declaration, not a language, so an hreflang goes through `alternateLanguage(alternate)`, which returns `null` for it (and for a blank). Carrying the phantom `'x'` forward once had `ua/state-language-version-lesser` reporting a Ukrainian page deficient against "its x counterpart", statute cited.
- **`normalizeLanguageCode` vs `normalizeBCP47`** — strict, never-hyphen-splitting for URL path segments and picker label text; the BCP-47 variant only for `hreflang` / `<html lang>`. Using the wrong one on `/ru-return-warranty` yields `'ru'` when it must yield `null` (the Bosch regression, guarded by a test in `url-language.test.ts`).
- **Page scope implies `static`.** The kernel adds it to a page-scoped rule's required capabilities, so an empty bundle is `not-collected` rather than vacuously passing.
- **`textNodes` is a sample; `textSampling.examined` is the population.** The collector caps body sampling at `MAX_TEXT_NODE_SAMPLES` (1500), so `page.document.textNodes.length` is a floor, never a census. Take the denominator from `textSampling.examined` — `textNodeDenominator()` does — and **call the helper: a body-text denominator is never a hand-assembled literal**, however local it looks. The migration that introduced it walked the helper's existing call sites rather than every place a denominator is made, so `served-language.ts`'s `classifiedPageLanguage` went on quoting the cap after the counts reached the wire (#483). Scope that rule to body text and no wider: `content-language.ts`'s `headDraft` correctly assembles its own, because its `examined` counts _head fields_ — `textNodeDenominator` would be flatly wrong there, and its doc comment says so. `classifiedPageLanguage` is the kernel's seam rather than one rule's, so its floor did not stay one page's: `mergedDenominator` **sums** one denominator per determination, so a hybrid family-C `core/serving-*` finding compounds the understatement with every page it cites — two truncated responses read as _"4 of 4"_, a unanimous verdict on the whole of both, where the walker had examined 1400 nodes between them. The sentence that quotes such a count says plain _"text nodes"_ and reads its numbers off the denominator the finding carries, so the two cannot drift apart: _"sampled text nodes"_ names the sample, which is exactly what the denominator is not. (`ua.ts`'s truncation note says _"N of M examined text nodes"_ because it really is quoting a `sampled of examined` pair — a different thing, said explicitly.) Check `textSampling.cappedAt !== undefined` before comparing two pages by text volume, since above the cap every page measures identically. **Ask with the flag, never with `examined > sampled` and never against a hard-coded `MAX_TEXT_NODE_SAMPLES`** — that constant is the collector's, and the kernel adjudicates bundles from collectors it has never seen. `ua/state-language-version-lesser` is the rule that has to: its volume half compared two truncated sums silently, so a Ukrainian version genuinely a third the size of its counterpart read as exact parity when both overflowed, and a pair straddling the cap published a 92 %-deficit `fail` — statute cited — that belonged to the collector rather than the site. It now refuses the pair and emits a `declared`/`info` "content volume was not measured" finding naming the truncated side and its `sampled of examined` counts. Refusing without saying so would be the same silence one layer down: a rule that reports `pass` on a pair it never measured. The counts only reached `Evidence` in `schemaVersion` 3: for two versions `digestFromDocument` computed the report and both collectors dropped it on the floor, so a 4000-node page published "3 of 1500 text nodes" and overstated its own share by 2.7 × — in the direction of the accusation. That is why the report is now a field of the `DocumentEvidence` the digest builds rather than something each collector must remember to copy across. A bundle written before v3 carries no counts and falls back to the sample length, which is exactly what it used to quote.
- **`text-samples.ts` owns "may this text be classified?" — and owns the page-level vote that reads it.** The gates (`MIN_CLASSIFIABLE_CHARS`, `isProperNounRun`, `isInsideCodeElement`) are not one family's taste; the module doc says in as many words that two copies of the question would drift into two answers to the only thing that decides whether a passage gets cited in a document naming a company. Families A and E went through `classifySamples` and were gated. Families C, D and F did not: `served-language.ts`'s `classifiedPageLanguage` and `ua.ts`'s `classifyDefaultLanguage` each ran their own vote over raw `sample.text`, so three families classified text the catalogue excludes — three samples, two two-character words and one `<code>` node, where the shared gate keeps zero, published `{"language":"uk","via":"classified","denominator":{"examined":3,"matched":2}}` (#435). `via: 'classified'` costs such a finding its failing power, which is why this stayed invisible, but the observation still names a site and still rests on nothing — and in `core/switch-no-effect` the determination is not merely reported, it is the **test**: `served?.language !== source` returns no draft, so a fabricated verdict naming any other language silently suppresses a real finding. The vote now lives once, as `dominantSampleLanguage(classify, page, candidates)`, which is `classifySamples` plus the majority count plus `textNodeDenominator` — call it rather than counting verdicts yourself, exactly as you call `textNodeDenominator` rather than writing the pair. The one parameter that is legitimately per-caller is `candidates`: families C, D and F ask "of the languages this site **declares**, which did it serve?", so they narrow to the site's own set and `classifySamples` takes it as an argument defaulting to `CLASSIFIER_CANDIDATES`. That default is not a formality — the widest roster makes the classifier abstain where a narrow pair commits, so the same brand-name string is `null` against `uk/ru/be/bg/en` and `ru` against `uk/ru`. Narrow only where the question really is about a declared set, and never think of narrowing as loosening a gate; the gates are not parameterised and must not become so.
- **A text sample's `nodePath` cites the passage, not the element around it.** `<p>A<br>B</p>` — and every paragraph with an inline link in it, which is ordinary prose rather than an exotic shape — is several sibling text nodes under one element. Handing them all the parent's path made `core/lang-part-unmarked` publish two findings identical in **every** field: same `subject`, same `evidence`, same summary, same denominator, so the report read as one finding printed twice rather than as two passages, and a reader could not tell which passage either one meant. `core/content-language-mixed` has the same defect one level in — its `citedNodes` quoted a single location N times inside one finding that claims to cite N passages. `digest-dom.ts` now appends ` :: text(n)` where a parent holds more than one passage, exactly as `:nth-of-type` disambiguates one level up, and **only** where it disambiguates: a paragraph holding a single passage keeps the path it has always published, so citations quoted in earlier reports do not churn and stay valid CSS. The ordinal counts the parent's non-blank child text nodes — a property of the **document**, never of what the collector kept — because a second collector with different sampling gates must still produce the same string for the same passage, so `MIN_SAMPLED_CHARS` and the 1500-sample cap do not move it. Two costs, both accepted: a path that carries the suffix is no longer a selector you can paste into `querySelector`, and inserting an inline element into a paragraph renumbers that paragraph's passages — the same churn `nth-of-type` has always had. The kernel parses these strings in exactly one place, `isInsideCodeElement` in `text-samples.ts`, which splits on `[\s>+~]+` and matches each step's leading element name, so the `::` and `text(n)` steps are inert there and a `<code>` block holding two passages is still excluded from classification. A bundle stored before `schemaVersion` 5 keeps its ambiguous parent paths, which is what it was collected with; nothing recomputes them.
- **A rule that only emits `observation` / `info` findings verdicts as `pass`.** Observations are cited, never scored — the headline is `brokenPromises`, the count of `fail` findings.
- **`RULESET_VERSION` reads `package.json`.** It floats deliberately; a pinned ruleset is one nobody bumps. Don't hard-code it.
- **A new workspace member needs its own `vitest.config.ts` declaring the `json-summary` reporter**, or it vanishes from the repo coverage denominator and trips [`metrics-gate`](../../docs/metrics-gate.md) — a 100 %-covered new package can still fail the gate.
- **Resolve declared targets through `src/locator.ts`, never by comparing strings.** The same page is legally written `https://example.com/uk/`, `/uk`, and `/uk/index.html`, and hreflang is absolute while filesystem evidence is a build path. A raw `===` silently reports a correct site as unresolvable — it did exactly that to `ua/state-language-version-lesser`, whose page pairs never matched off disk. `src/locator.test.ts` guards the equivalence class. **Resolve with the declaring page as the base, too** — `parseLocator(href)` with no base resolves a relative href against the site root, so `../uk/guide.html` declared on `/docs/en/guide.html` became the literal path `/../uk/guide.html` and a bare `./` self-reference became `/.`. Family B's hreflang rules parsed without one and false-failed `core/hreflang-target-unresolvable` on correct markup — markup `core/hreflang-target-relative` only _warns_ about, so the catalogue expects it. `resolveTargetPage(pages, from, href)` threads the base for you; prefer it to a bare `parseLocator`. **A host-less locator still matches any host — but `resolveTargetPage` asks the declaring page whether it lives somewhere else.** `sameLocation` stays permissive, which is what recognises a self-reference and a reciprocal alternate; that is right for a _relative_ href, which carries no origin to disagree with, and wrong for an absolute one, where `hreflang="uk" href="https://other-brand.de/uk/"` matched a local `/uk/index.html` on a shared path alone — passing `core/hreflang-target-unresolvable` on a page never collected and failing `core/hreflang-target-wrong-language` with the local file's `lang` attributed to a host it never came from. So a host-naming href is checked against the origin **the declaring page claims for itself** (`claimedOrigins`): the URL it was collected from, or the alternate that points at its own path _in its own `<html lang>`_. Three rules there, each of which a bug already broke: read the claim **per page**, never pooled across the page set, or a host one page named as its target becomes an origin another page is answered for — the inference this module exists to refuse; require the **language** match, or a reciprocal alternates block (every page in a translation set carries the _same_ one) lets a foreign host sitting at the declaring page's own path claim itself; and when a page claims **no** origin, keep the permissive match, because an unknown origin is not a foreign one — failing there turns a `warn`-grade missing self-reference into 24 hard `fail`s on targets that are sitting in the build. `locator.test.ts` pins all three.
- **The page set's dedupe must not swallow how a page was reached.** `createPageSet` in `src/collect/assemble.ts` keys pages by URL _and_ body identity, and a probe landing on a document already in the set gets the existing id back instead of a second page. `reach` is the one field on that page which is not a property of the bytes — it records how the audit _got to_ it — so handing the id back untouched threw information away. The self-referential `<link rel="alternate" hreflang="en" href="https://example.com/">` that sits on half the web is the case: `--follow` fetches it, the fetch succeeds, the body is byte-identical to what the matrix already collected, the page keeps `reach: 'requested'`, `hasTraversal` finds no `declared-target` page, and `core/hreflang-target-unresolvable`, `core/hreflang-target-wrong-language`, `core/picker-target-unresolvable` and all three `core/switch-*` rules read `not-collected` on a run that followed every declared target and resolved every one of them. `not-collected` is never `pass`; announcing that the collector lacked a capability it exercised is that same dishonesty pointed the other way. `add` now upgrades the stored page's reach, and only ever upward (`requested` → `declared-target`, never back), so the fold is order-independent for a collector that interleaves the matrix and the expansion. The upgrade stays an **observation**: it happens on a probe that actually landed, so a declared target the collector never reached still withholds `traversal` — the opposite overshoot, granting a capability off the dedupe alone, would be the same lie in the other direction. The redundant second fetch is still spent against the budget on purpose: whether a target dedupes onto a collected page is only knowable from its _final_ URL and body hash, so skipping the request would mean inferring the answer from the URL that was asked for.
- **An error document is not a page, and the page set is where that is refused.** Every body handed to `createPageSet` in `src/collect/assemble.ts` carries the `status` it was served with, and anything outside 2xx is refused: `add` answers `null`, and the collector records a probe with no `pageId`. A `404` replies with an error template — the site's own markup, its own `<html lang>`, no relation to the page the declaring markup promised — and digesting one made it a real `declared-target` page, after which every rule that resolves a declared target read the stub as that promise kept. `core/hreflang-target-unresolvable` resolved `hreflang="uk"` to the 404 and published **`pass`**, which is "`not-collected` is never `pass`" inverted: the page it passed on is the one page the site had just said does not exist. `core/hreflang-target-wrong-language` then read the error template's `lang` and published a `fail` attributing English to a Ukrainian version nobody ever served — a false accusation about a named company, assembled entirely out of a page the site said was not there. [`docs/movar-audit-rules.md`](../../docs/movar-audit-rules.md) already grades a 404 target `fail` ("Declared target 404s"), so the collector was contradicting the published catalogue. **Deliberately not a fourth `ProbeOutcome`**, which is where the fix looks like it belongs: `adjudicableProbes` drops every non-`ok` probe, and `unresolvableDraft` is written to _cite_ this one — it says "returned a 404 response" instead of "is absent from the collected page set" only when it can see the probe. A 404 is a real observation about the site, unlike a challenge interstitial (`blocked` — somebody else's page) or a transport failure (`error` — nothing observed), so the probe stays `ok` and complete, status, headers and chain included, and only the _page set_ narrows. Refused by the set rather than asked of each caller because the Safari host app assembles its own probes and the Android port will too: "is this body a page?" is the same class of judgement as "is this `Link` header a declared alternate?", and two collectors answering it differently report different findings about the same site. The 2xx predicate itself (`isServedResource`) is exported, because a page is not the only body an audit is handed — see `fetchRobots` below, which asks it about `robots.txt`.
- **The head tier reads the head, and `querySelector('title')` does not.** An unqualified type selector matches every namespace, so `doc.querySelector('title')` in `src/collect/digest-dom.ts` took the first `<svg><title>` in the body of any page whose head declared none: an icon's accessible name collected as `field: 'title'`, and `core/title-contradicts-declaration` publishing an English tooltip on a Ukrainian page as _"this page's `<title>`"_ — cited by a node path running through `body`, so the sentence and its own citation contradicted each other. `<svg>` was already in `SKIPPED_ELEMENTS` for body sampling, so one digest disagreed with itself about one element. `htmlTitleOf` now takes the first `title` **in the HTML namespace**, which is exactly what `document.title` reads — deliberately **not** the first inside `doc.head`: a stray `<svg>` ends the head under the parser's _in head_ insertion mode, so a real `<title>` written after one is parsed into the body, where the browser still reads it and a head-scoped collector would answer "no title" about a page whose tab shows one. The namespace is the defect; the location is not. The two `<meta>` scans had the same document-wide reach and are head-scoped instead (`headMetasOf`), because there location _is_ the whole problem: `<meta>` in the body is valid (`itemprop` microdata) and routinely script-injected, and one carrying `http-equiv="content-language"` made `core/lang-contradicts-content-language` publish a `fail` — _"the page contradicts its own head"_ — about a head that never declared it. A `<meta>` the parser moved out of the head is now missed rather than misattributed, which is the accepted direction: a missed violation is recoverable, an accusation against a compliant site is not.
- **A differential rule is admitted because _some_ two readings differ — so it must never cite by position.** `core/serving-decided-by-ip` filtered legs on `distinct(languages).length >= DIFFERENTIAL_MINIMUM` and then built its finding from `readings[0]` and `readings[1]`. With three or more vantages the differing pair sits anywhere, so the rule published a `fail` whose own summary quoted `<html lang="uk">` twice — accusing a site of geo-routing while showing no difference at all, and the accusation is worded around a vantage's country _claim_, which makes an undemonstrated pair worse, not milder. `differingPair()` is now the single gate: the same call admits the leg and returns the pair the summary quotes, so the test and the citation cannot drift apart again. The full reading set stays in `evidence` — only the citation narrows. Latent while a collector is single-vantage, but `Evidence` is the public API and a merged bundle can carry three vantages today.
- **`core/lang-part-unmarked` cannot actually `fail`,** though the catalogue grades it so. Its "is this passage foreign?" question has no declarative answer — an element that declares its language passes by definition — so `via` is always `'classified'` and the kernel downgrades it. That is the safe behaviour; the catalogue row is what is out of step.
- **The CLI's exit codes are three-valued.** `0` clean, `1` red (uncovered broken promises, a policy that breaks the doctrine, or a stale entry), `2` the run never happened (no source flag, an argument `parseArgs` refuses, a `--dist` that is not a readable directory, an unreadable or unparseable policy file). A CI step that treats every non-zero as "the site is broken" will report a typo in a path as a language defect — and `1` accuses the site, so only an audit that actually ran may return it. **Every path the operator names is checked before anything is collected from it.** `collectFilesystem` calls `readdir` unguarded, so a mistyped `--dist` used to leave an uncaught `ENOENT` to reach the top-level `await` — and a top-level rejection exits `1`, so the typo did not merely crash, it crashed wearing the exit code of a language defect. `checkDist` in `src/collect/cli.ts` now `opendir`s the resolved path first (`opendir`, not `stat`: an unreadable directory `stat`s perfectly well and then fails the `readdir` that matters) and refuses with `could not read <path>`, `readPolicy`'s own wording, plus `no such directory` / `not a directory` where the errno says which. It is a pre-flight on that one path and never a `try` around `collect()` — a subdirectory that will not list, a file that will not read or a parse that throws is a real defect or a broken machine, and must still surface as a crash rather than be dressed up as a mistyped path. The path is named **as resolved**: `--dist dist` is the form the dogfood gate invokes, and "no such directory: dist" cannot tell an operator their shell was somewhere else. **Every token in argv must be accounted for**, which is one of those refusals: `parseArgs` walks argv and rejects anything that is not a known flag or the value of one, naming it. It used to look each known flag up by name and never enumerate argv, so a typo was invisible — `--budgt 5` audited with the default budget of 40 and said nothing, `--folow` quietly left the traversal off, and both govern how this tool behaves toward a site that never agreed to be audited. `USAGE` documents no positional argument, so a stray token (`-budget`, a shell glob, a path that lost its `--dist`) and a bare `--` are refused by that same walk — there is no end-of-options separator, because there is nothing positional to separate.
- **`parseArgs` answers `Args | Error`, and validates rather than coerces.** A `--budget` must be digits that survive `Number.isSafeInteger`, and no flag may take the next flag as its value. Both were `2`-worthy typos that used to run: `Number('lots')` is `NaN`, which loses every comparison the request ceiling in `probe.ts` is made of (`spent >= NaN` is false forever, `remaining()` is `NaN` and never `=== 0`), so a mistyped budget silently uncapped an audit against a live third-party site; and `--url --follow` parsed as a url of `--follow` and went and fetched it.
- **The CLI's entry-point guard compares resolved real paths, never basenames.** `isProcessEntryPoint(import.meta.url, argv[1])` in `src/collect/cli.ts` decides whether importing the module launches an audit, and it `realpathSync`es both sides — which is the only reason the declared `bin` works, since `argv[1]` is then the `node_modules/.bin/movar-audit` symlink and only its target is that file. The basename comparison it replaced was wrong in both directions at once: `…/collect/cli.ts` never ends with `movar-audit`, so `movar-audit --url …` audited nothing and exited 0; and any unrelated process whose entry script happened to be named `cli.ts` matched, so importing `@movar/audit/collect/cli` started a live audit. `nx run marketing:audit` runs `tsx …/collect/cli.ts` directly — the one shape the old guard fired for — so a regression here fails silent and green rather than red. `cli.test.ts` pins all four shapes.
- **`cli.ts` is committed executable (`100755`), and that is the `bin` field's doing, not an accident.** pnpm chmods every declared `bin` target `+x` when it links it, so each `pnpm install` re-sets the bit on `src/collect/cli.ts` — the one source file in the workspace named by a `bin`. While git recorded it `100644` the two disagreed permanently: every install dirtied the tree with a mode-only diff that survives `git checkout .`, blocks a branch switch, and reappears the moment you strip it. Committing the mode git was always going to be handed ends that, and costs nothing — the file has no shebang and is never exec'd directly (`nx run marketing:audit` runs it through `tsx`; the `bin` route goes through the symlink and the entry-point guard above). **Do not "restore" it to `100644`**: the next install will just flip it back.
- **`sideEffects` names the CLI, and must keep naming whatever file carries that guard.** `package.json` declares `"sideEffects": ["./src/collect/cli.ts"]`, not `false`. The flag is a promise to a bundler, and `false` was a lie about exactly one file — the one whose entire job at import time is to run an audit. What it licenses is **dropping a module that is imported and whose exports go unused**, which is not the CLI-as-entry-point shape it looks like: esbuild and rollup both keep an entry point's module-scope statements whatever the flag says. It is the **thin-wrapper** shape — `import './cli.ts'` for its effect alone bundled to the empty string, guard and `runCli` and all. That makes this a booby trap rather than a cosmetic untruth, because a thin executable wrapper importing a quiet module is precisely the restructure the `bin` and publish work both reach for (see #498): written while the flag said `false`, it compiles to a `movar-audit` that exits 0 having audited nothing — #437's failure mode, arriving through the packaging metadata instead of the guard. `src/packaging.test.ts` pins both halves with a real `esbuild` bundle, because only a bundler can falsify a claim about what a bundler will do: the CLI survives being imported for its effect, and the kernel barrel still tree-shakes to nothing, which is the reason the flag is here at all. **Add any new module that does work at import time to that array** — the array cannot be derived, because a bundler cannot tell "has an effect" from "could not be proven not to": with the field ignored (`--ignore-annotations`) esbuild keeps 102 KB for a bare `src/index.ts` and 6 KB for `src/collect/node.ts`, neither of which has a module-scope statement at all. It moves to the emitted paths when the publish milestone compiles to `dist/`.
- **Every rule the CLI prints carries why it did not run.** `formatResult` in `src/collect/cli.ts` appends the kernel's `notApplicableReason`, or `needs <capabilities>` built from `missingCapabilities`, to the rule's own line; a rule that ran gets nothing appended, since its verdict and findings are the explanation. Two thirds of a typical run are rules that did not run, and the CLI used to print their ids and drop both fields — `? not-collected (11)` told an operator nothing about whether a second page or `--follow` would have run them. Presentation only: the `Report`, the `--json` payload and the exit code carry the same values either way.
- **A broken suppression silences nothing.** An entry that fails validation is reported and then ignored, so a malformed suppression is never more powerful than a well-formed one. The budget is likewise checked against the _declared_ entries, not the surviving ones.
- **A suppression's `subject` is decided by the _finding's_ scope, never the rule's.** They are different claims: a rule's `scope` says how the kernel iterates it, a finding's says what the finding is about, and `gradeFinding` keeps them apart (`draft.scope ?? rule.scope`) so a rule adjudicated once for the whole run can still name one URL per finding. Every family C rule does exactly that — `scope: 'site'` on the rule, `scope: 'page'` on every draft. Keying the check on the rule stood doctrine 2 on its head for all seven: the entry naming the offending URL was refused and the site-wide entry was the only legal form, so one misbehaving URL cost a team the rule across its whole site. A `subject` is now permitted when any of the rule's findings is page-scoped and required when all of them are — and when the rule emitted no findings at all (it passed, or read `not-applicable` / `not-collected`, which is what family C does on filesystem evidence) the rule's own scope is the fallback, so a rule falling silent never makes a blanket entry legal. Doctrine 5 still reports such an entry stale, matched by subject or not.
- **Never default an absent count to `0`.** `pagesAdjudicated` / `pagesNotApplicable` (on a `RuleResult`) and `coverage.rulePagesAdjudicated` / `rulePagesNotApplicable` are optional, and `0` is a real value that means the rule judged nothing — distinct from absence, which means nobody counted. Absence has three causes: a site rule (it iterates no pages), a `not-collected` rule (never called), and a stored report written before the counts existed. That last one is the whole cost of leaving `REPORT_SCHEMA_VERSION` at 1 while `EVIDENCE_SCHEMA_VERSION` bumps on every additive change: **presence is the discriminator**, since a page rule with any verdict but `not-collected` and no counts predates them. The two constants diverge on purpose — `Evidence` has one version per collector runtime and `Report` has one producer — and each says so at its definition.
- **"Invoked" is not `coverage.ran`.** The per-page counts are summed over every page rule the kernel **invoked**; `ran` excludes `not-applicable`. A rule invoked on all 20 pages that found nothing to adjudicate on any of them contributes 20 rule-pages and is _not_ in `ran` — on movar.fyi that is 120 of the 186 skipped rule-pages. The unit differs too: `coverage.rulePages*` counts rule-pages (one rule's look at one page, so it exceeds the page count), `RuleResult.pages*` counts distinct pages for one rule. Related: `notApplicableReason` is the **first** of `notApplicableReasons`, kept for a one-line render; the list is the complete set of distinct reasons, in first-seen order. A page rule that skips three pages for three different reasons used to report the first as though it were the rule's.
- **The npm publish train is a later milestone.** The package is `private: true` and exports raw TypeScript like every other member; the tsup `noExternal` bundle, provenance, and its own release train land with the CLI.
- **`createProber` validates its own ceilings, so "enforced here rather than trusted to callers" is true of every caller.** `budget`, `maxHops`, and `timeoutMs` must each be a non-negative safe integer, or construction throws a `TypeError` — the `parseArgs` guard above only covers the CLI, while `createProber` is reachable from the `./*` subpath by any direct caller: a relay, a test harness, a future in-process collector. `collectNetwork` is still the only in-repo one; the Safari host app collector took the native path in #422 (`COLLECTOR_ID = 'swift-urlsession'`) and enforces its own budget in `AuditProbe.swift`, so it never constructs a `Prober`. This is a deliberate **`TypeError`, not `RequestBudgetExhaustedError`**: that error reports a run that reached its ceiling and a caller may catch it to report partial coverage, so a construction bug routed through the same class would be swallowed by that handler. Nothing should branch on the validation failure, so it stays unexported. Zero is legal for all three (spend nothing / follow no redirect / abort at once) — the guard is a range check, never a falsy one.
- **A robots.txt value is an RFC 9309 pattern, not a prefix, and a run of `User-agent` lines is one group.** §2.2.3 makes `*` any sequence and a trailing `$` the end of the match, so `robotsAllows` asks `robotsPatternMatches`, never `startsWith` — matching literally left `Disallow: /*/private`, `/*.json$` and the near-universal `/*?` inert, and the failure direction is the collector fetching paths the site asked it not to. That matcher scans the literal runs between the `*`s with `indexOf` instead of compiling a `RegExp`: robots.txt is attacker-controlled text from a third-party origin, and the naive translation of `/a*a*…*b` spends 65 s on a 41-character path where the scan answers a 50 000-character one in well under a millisecond. A `$` is handled by appending an end sentinel to pattern and path alike, so the anchored case stays that one shape rather than a second one. Longest-match-wins still reads the pattern's own length, metacharacters included, so the patterns are stored verbatim. §2.2.1 is the other half: consecutive `User-agent` lines head **one** group applying to all of them, so `parseRobots` opens the group when _any_ agent in the run is `*` and only a rule line ends the run (a blank, a comment, a `Sitemap:` does not). Overwriting the flag per line made the group order-dependent — `*` then `Googlebot` dropped `/private` entirely while `Googlebot` then `*` honoured it. §2.2.2 is what the **call site** owes the matcher: a rule matches the path _and_ the query, so the expansion's robots gate hands it `robotsSubjectOf` — `pathname` + `search` — never a bare `URL.pathname`. A correct matcher is inert without that: stripping the query left `/*?` unable to fire on any real declared target, and a language switch carried in the query (`?lang=`, `?hl=`, `?locale=`) is precisely the declared target whose query is the whole point of it. Test that end to end at `followDeclared`, not only at the matcher — a matcher-level assertion passes while the expansion still fetches.
- **A chain past `maxHops` is evidence, not an error — and it must never read as a finished one.** Every exit from `walk` in `src/collect/probe.ts` answers with the last response it actually got; a `null` response is reserved for a transport failure that observed nothing, because `resolveOutcome` reads `null` as `error` and `adjudicableProbes` drops an `error` probe before anything — capability derivation included — sees it. Falling out of the hop loop used to answer `null`: eleven requests spent against a live third-party site, the whole chain sitting in `redirectChain`, `http` not even derived, and `core/switch-bounces` — the rule this module walks chains one hop at a time _for_ — handed nothing at all. What made it plainly a bug rather than a policy: a **cyclic** chain exits through the `seen` check with a live response and stays fully adjudicable, so a 2-hop loop was evidence and an 11-hop chain was discarded. The ceiling now answers with the last 3xx and sets `redirectChainTruncated`, and **`status` is that 3xx rather than `0`** — `0` claims no response at all, which is false of eleven of them. The flag carries the whole of the honesty the old `0` was standing in for: the last hop's `Location` names a URL nobody fetched, so `core/switch-bounces` publishes a truncated chain as an `observed` `warn` naming the hops it did see, never says where it "lands", never grades it a bounce, and never lets it settle into `pass` — passing off a chain whose end nobody saw is the same silence one layer up, and `not-collected` is never `pass` for the same reason. **Ask with the flag**, exactly as with `textSampling.cappedAt`: `maxHops` is the collector's, and the kernel adjudicates bundles from collectors it has never seen, so counting hops against a constant here reads one collector's ceiling into another's evidence. `AuditProbe.swift` still records its own ceiling as `error` / `status: 0` and so degrades to the old behaviour — the chain is dropped, never misread — until it carries the flag too.
- **A robots.txt binds one origin, so the expansion resolves one per origin it is about to touch.** A declared alternate routinely lives on an origin the operator never typed — the cross-domain locale pattern, `brand.de` beside `brand.pl` — and no site's robots.txt has authority over another's. `createRobotsGate` keys `new URL(target).origin` into a per-origin cache and evaluates each target against its **own** origin's rules; reading the typed URL's single copy over all of them was wrong in both directions at once. `example.com`'s `Disallow: /de` withheld `https://example.de/de/`, and the gap that left in the page set published `core/hreflang-target-unresolvable` as a `fail` — "the declared alternate cannot be reached" — about a page `example.de` serves perfectly well, which is a false accusation about a named company. And `example.de/robots.txt` was never requested at all, so "honoured for declared-target expansion" was true of the first origin only. The cache stores refusals **and** failures: N targets on one origin cost one request, and an unreachable robots.txt is not re-asked per target. An unfetchable or unreadable one is still permissive (`EMPTY_ROBOTS`) — that semantic is unchanged, and **a non-2xx one is explicitly in that class**: rules are parsed from a body the origin actually served (`isServedResource`, the predicate the page set refuses an error document on) and from no other. A site answering `404` for `/robots.txt` published no rules — RFC 9309 §2.3.1.3 — and what it answers _with_ is an HTML error template, so parsing that asked a "not found" page which paths this crawler may fetch. Today's templates yield nothing, since a directive must survive `parseRobotsLine` as a whole line, but that is a property of their markup and not a guarantee: a `Disallow:`-shaped line in an error page or a syntax example withholds a target the site permits, which `unresolvableDraft` then publishes as `fail … "cannot be reached"` about a page that serves — the same false accusation per-origin resolution exists to kill, arriving by way of the error page — and an `Allow:` in one manufactures permission the site never gave. A `5xx` stays permissive with everything else here, deliberately not §2.3.1.4's optional "assume complete disallow": a transport failure is already read as "no rules published", and a server too broken to answer is not a site that asked for anything. A target with no fetchable origin — a picker's `javascript:` href — is neither asked about nor charged for. `--ignore-robots` short-circuits the gate, so it costs no request either.
- **The budget for that expansion is re-read, never reserved, and it buys the pages the audit does not already hold first.** Both halves are load-bearing and both were learned the hard way. **Re-read:** `probe` charges a request **per redirect hop** — `spend()` sits inside `walk`'s loop — so a `robots.txt` that 301s (`http`→`https`, `www`→apex, CDN normalisation) costs two, and no fixed reserve can be sized against a hop count that is not knowable before the fetch. A reserve of two therefore bought the target nothing and the probe behind it threw `RequestBudgetExhaustedError` out of `collectNetwork` on a run that completes on `main` — `main` was safe only because its single robots fetch happened _before_ the loop whose top re-checks `remaining() === 0`, and moving the fetch inside the iteration, after that check, removed the guarantee. So `followDeclared` re-checks the ceiling **after** the gate returns and before the probe, and `fetchRobots`' `catch` reads a chain that hits the ceiling mid-redirect as "no rules published" — nothing is ever fetched on the strength of rules nobody read, because the re-check stops the run first. `false` from the gate consequently means one thing only: the site said no. **Pages first:** a reserve sized to be safe withholds targets the budget could have paid for, and a withheld target is not a silence — `unresolvableDraft` publishes it as `fail … "cannot be reached"` about a site that serves the page, which is the same false accusation per-origin resolution exists to kill, arriving by way of the budget. `budgetOrderOf` therefore puts declared targets the page set does not already hold ahead of ones it does: a target already collected can only add a `reach` upgrade, so spending a scarce budget in markup order let the ubiquitous self-referential `<link rel="alternate" hreflang="en" href="/">` crowd out the cross-origin alternate behind it. **Test every budget path against the ruleset, never against the fetch log alone** — the two budget tests that asserted request lists only are exactly why a verdict flipping from `pass` to `fail` about a named company got through review.
- **`ua/state-language-version-lesser` counts its two sides differently, and must.** To say the Ukrainian version is lesser you need a _lower_ bound on the other language's version count and an _upper_ bound on Ukrainian's, and those point in opposite directions. Other languages are counted by **version** — `versionsOf` groups the page set by normalized location and by the hreflang alternates the pages themselves declare, and each version counts once per language — because a page count is a property of the crawl: `/` copied from `/en/` is one version enumerated at two paths, one URL observed from two vantages is one version observed twice, and counting pages read `en: 2, uk: 1` on a build with exact 1:1 parity with Law 2704-VIII stamped on it. **The Ukrainian side is page-counted end to end — `served` and `credited` alike, and nothing on it may consult `versionsOf`.** That, precisely and only that, is the safety property. It is _not_ "merging only joins" (false), and it is _not_ "merging is barred from the Ukrainian side" (believed once while `credited` quietly iterated versions, which is how the second false positive shipped). Version-counting is safe on the side that needs a lower bound and unsafe on the side that needs an upper one; `credited` sits on the upper-bound side, so writing it in the lower-bound idiom manufactures deficits. Both failures were the same shape at exact parity: three Ukrainian pages each declaring `hreflang="uk" href="/uk/"` — the widespread "alternates name the language homepages" pattern — collapsing into one version; and then three _English_ pages naming one another, collapsing three credited Ukrainian counterparts into one while the Russian count stood still. For the same reason `x-default` and a blank `hreflang` never merge (`alternateLanguage` is `null` for both): cluster membership feeds a per-language count, so a routing hint would otherwise decide which language is deficient. Nothing needs them; #441's duplicated root is unified with `/en/` by its own `hreflang="en"`.
- **The guard is a property test, not a list of sites.** `ua.test.ts`'s "adding hreflang to the _N_ pages alone keeps it passing" cases assert that an hreflang alternate on pages that do not serve Ukrainian can never turn a `pass` into a `fail` — it may shrink the other-language side, and must not move the Ukrainian one. It mutates **one `<html lang>` group at a time**, on purpose: mutating every non-Ukrainian page at once collapses both sides symmetrically and hides exactly the defect being guarded. Three hand-built false positives got through review before this existed; each was one more corner of the same property.
- **The Ukrainian credit is a deliberate, documented hole.** A collected page naming a Ukrainian counterpart that parses to a locator but was never collected counts toward Ukrainian: the absence is a fact about the crawl budget, and probing the href is the one thing this pack may not do. The href must **parse** — `href="#"` and `href=""` declare no target (`parseLocator` answers `null`, and locator.ts says so), and crediting them let markup asserting nothing silence a statutory check. Consequence to know before you trust this rule's silence: a site can suppress the count half with a fabricated `uk` alternate per page, and on a network run **nothing need report it** — `core/hreflang-target-unresolvable` needs `traversal`, which network evidence carries only when some page was reached as a declared target, so a run whose declared targets all dangle produces no such page and that rule reads `not-collected`. One target that resolves lifts the gate for the whole bundle, and a self-referential alternate is one, so the hole is narrower than it looks and closed entirely off disk, where traversal is free. A target that **404s** counts as dangling only since the page set started refusing an error document (see the bullet above): while the 404's template was digested as a page, the fabricated alternate resolved to it, lifted the gate on its own and made that rule read `pass` — the hole plugged by a false statement rather than left open by a missing capability. That cost is accepted on the pack's standing bias: a missed violation is recoverable, a statute-citing accusation against a compliant site is not. `ua/state-language-absent` already carries the identical hole, passing on a declared-but-unverified `uk` alternate.
